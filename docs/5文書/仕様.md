# 仕様 — Giftia 送別ギフトの「決めきれない」を解決する

前提: モック。2026-11-17（火）の週までは手元のパソコンで動かす（画面は Next.js の http://localhost:3000、API は FastAPI の http://localhost:8000）。その後 Azure にデプロイする予定（ADR-0009）なので、下の URL の `localhost` の部分はデプロイ先で変わる。DB は班の Azure Database for MySQL（開発用）。ログインはない。

## 全体像

贈る人が候補を3つまで選んで共有リストを作り、URL を同僚に送る。同僚はその URL を開き、名前を入れずに（匿名）候補に賛成し、賛成した候補には「いいと思った理由」を、候補ごとにひとことを送る。贈る人は、集まった声をもとに Giftia が決めた1位と理由を見て、1つの商品の購入ボタンを押す。

```
贈る人 ①検索 → ②候補を選ぶ → ③共有URLを作る ──(LINE などで人が送る)──▶ 同僚 ④答えて賛成する
贈る人 ⑤集まった声を見て、購入ボタンを押す ◀── DB に保存された賛成・コメント
```

①〜⑤は、班のワイヤーフレームの画面の番号。

## 画面・操作
<!-- 画面ごとに ### で分ける -->

### ① 条件を入れる（贈る人）— F-01（開発①では変えない）
- 今ある検索画面（`/`）をそのまま使う。入力欄・検索 API には手を入れない（ADR-0008）。見た目だけ、下の「全部の画面に共通」に合わせる
- 開いた時点では、ふつうの Giftia の検索だけを出す（ステップ・「候補に入れる」・下のバーは出さない）。上に「みんなで選ぶ」の入口（説明とボタン）を出し、押すと同じページのまま②になる（URL は `/` のまま。再読み込みすると、ふつうの検索に戻る）

### 全部の画面に共通（デザイン。ADR-0016）
- いちばん上にヘッダー：ロゴ「Giftia」と「みんなで選ぶ」（トップで「みんなで選ぶ」を押す前は、右上の「みんなで選ぶ」は出さない）
- 待っている間（検索中、③④⑤を開いたときの読み込み中）は、画面の中央にくるくる（読み込みの印）と「検索中…」「読み込み中…」を出す
- 色：紺（#1b3a5c）をメインに、背景はあたたかい白（#f7f4ee）。金は飾りだけ。ロゴと見出しは明朝（Noto Serif JP）、本文はゴシック（Noto Sans JP）
- 贈る人の画面（②③⑤）の上に、3つのステップ「候補を選ぶ → みんなに聞く → ギフトを決める」と、今いるステップを出す
- 商品カードには、カテゴリーごとのダミー画像をサムネイルとして出す（商品ごとの画像はないため）。画像は `giftia-frontend/public/images/categories/`
- ショップ名（`products.brand`）は、商品名の上に小さく別の行で出す。商品名は `products.product_name` をそのまま出す（頭にショップ名が重なっていても取らない）

### ② 候補を選ぶ（贈る人）— F-03
- ①で「みんなで選ぶ」を押すと、上にステップ、カードに「候補に入れる」、画面の下にバーが出る
- 今の検索結果（人気順の上位20件）を、サムネイル付きのカードで並べる。カードには「人気◯位・ショップ名」・商品名・価格・評価
- 商品ごとに「候補に入れる」ボタン。押すと「候補に追加済み」になり、もう一度押すと外れる。3つまで選べる。4つ目は選べない
- 画面の下に「候補 ◯/3」、選んだ候補のサムネイル、「共有リストを作る」ボタン（1つ以上選ぶと押せる。作っている間はボタンの中にくるくるを出す）
- 全件数・次の20件・「評価なし」の表示（F-02）は開発①では作らない

### ③ 共有URLを送る（贈る人）— F-03
- パス：`/s/{share_id}/created`
- 選んだ候補3つ（サムネイル・「候補◯・ショップ名」・商品名・価格・評価）、共有URL、コピーボタン、同僚に送る文の例を出す
- 共有URLは「今開いているページのアドレスの頭（`window.location.origin`）＋ `/s/{share_id}`」で作る。`localhost` を直接書かない（デプロイ後もそのまま使えるように。N-06）
- 「集まった声を見る」で⑤へ

### ④ 賛成・コメント（同僚）— F-04
- パス：`/s/{share_id}`（共有URL）
- 名前の入力欄はない（匿名。ADR-0010）。「匿名での回答となります（名前は入れません）」と出す
- 候補3つ（サムネイル・ショップ名・商品名・価格・評価）を出す
- 候補ごとに「賛成」ボタン。**1回の回答で、いくつの候補にも賛成できる**。押すと付き、もう一度押すと外れる（ADR-0014。#20 で相談中）
- 賛成した候補には、コメントとして「いいと思った理由」を**必ず1つ**選ぶ：「本人が欲しがっていた（まだ持っていなさそう）」「贈る相手にぴったりだと思う」「特別感があって記念になりそう」「実用的で使ってもらえそう」「好みを選ばず、誰からも喜ばれそう」「とくにない」。賛成していない候補では選べない。賛成を外すと、選んだ理由も消える（ADR-0013。#19 で相談中）
- 候補ごとに、ひとこと（自由記述・200文字まで・任意）
- 「送信する」ボタンでまとめて保存する。送っている間はボタンの中にくるくる（読み込みの印）を出す。送ったあとはボタンを消し、同じ場所に中央揃えで「送信完了しました。ご回答ありがとうございました。」と出す（もう一度は送れない。同じ人を見分けないため。ADR-0010）

### ⑤ 集まった声を見て買う（贈る人）— F-06・F-07・F-08
- パス：`/s/{share_id}/summary`
- 回答した人数（匿名。名前は出さない）
- 見出しは「みんなの声で、ギフトが決まりました」。その下に「回答した◯人の「賛成」と「いいと思った理由」をもとに、Giftia が1つに絞りました。」（ADR-0016）
- 1位を中央揃えの大きなカードで出す：商品画像（500px の正方形）と、画像の左上にバッジ「みんなの声で選ばれたギフト」、ショップ名、商品名、価格、「選ばれた理由」、みんなのひとこと、「この商品を買う」。カードの右上の角に金のリボン（ADR-0016）
- 「選ばれた理由」の文（ADR-0012・0016）：1位の賛成数がほかのどの候補よりも多ければ「いちばん多くの人が賛成しました」。それ以外は「「本人が欲しがっていた（まだ持っていなさそう）」という声が決め手になりました」のように決め手の理由。決め手の理由が「とくにない」しかなければ「賛成した人の声をもとに選びました」
- 2位以下は、目立たない小さなリンク「その他の候補を見る（◯件）」の中にたたむ。リンクは1位のカードの中、「この商品を買う」の下に置く。開くと、F-08 の点数の順に、サムネイル・ショップ名・商品名・価格・ひとこと・「この商品を買う」を出す（ADR-0016）
- その下に、同じ目立ち方で「どうやって決めているの？」。開くと「賛成の数と、いいと思った理由の内容をもとに、スコアが高いギフトを選んでいます。スコアが同じときは、レビューの評価が高いほうを選びます。」（ADR-0016）
- **賛成数・「いいと思った理由」ごとの人数・点数は出さない**（ADR-0012）
- 「この商品を買う」ボタンは押すと記録し、「記録しました」と出す（今のアプリには商品ページがないため、開かない。決済はしない）
- 賛成が全部0なら1位は出さず、見出しを「みんなの声を集めています」にして「まだ1件も賛成がありません」と出し、全部の候補をたたまずに並べる

## 入力と出力

| 要件ID | 入力 | 処理 | 出力 |
| --- | --- | --- | --- |
| F-01（変えない） | `GET /api/search`（今のまま） | 今のまま | 今のまま。`results` の `id` を「候補に入れる」で使う |
| F-03 | `POST /api/shares` 本文 `{"product_ids": ["G0001", …]}`（1〜3個） | 共有リストを作り、候補を順番つきで保存する | `{"share_id": "UUID"}` |
| F-04・F-06 | `GET /api/shares/{share_id}` | 共有リストの候補を取る | `{"share_id", "items": [{"id","name","price","rating","position","brand","category"}]}`（`brand`・`category` はショップ名の行とサムネイルに使う。ADR-0016） |
| F-04 | `POST /api/shares/{share_id}/answers` 本文 `{"votes": ["G0001", "G0002"], "comments": [{"product_id": "G0001", "reason_key": "wanted", "body": "先輩っぽい"}, {"product_id": "G0002", "reason_key": "none"}]}`。`votes` は賛成した商品の ID（0〜3つ。ADR-0014。#20 で相談中）。賛成した商品には `reason_key` が必ず要り、賛成していない商品には付けられない（ADR-0013。#19 で相談中）。`body` は省略できる | API がランダムな回答番号（`answer_id`、UUID）を1つ作り、賛成とコメントをその番号つきでまとめて保存する。名前は受け取らない | `{"ok": true}` |
| F-06・F-08 | `GET /api/shares/{share_id}/summary` | 回答した人数と候補ごとのひとことを集める。F-08 の点数で並べ、1位と理由を決める | `{"respondents": 4, "items": [{"id","name","price","brand","category","comments": ["先輩っぽい", …]}], "top": {"id", "name", "why": "reason", "reason_key": "wanted"}}`（`items` は F-08 の順。`why` は `"majority"`（賛成多数）・`"reason"`（決め手。理由は `reason_key`）・`"voices"`（理由が「とくにない」だけ）のどれか。`reason_key` は `why` が `"reason"` のときだけ入り、ほかは `null`。賛成が全部0なら `top` は `null`）。**賛成数・理由の数・点数は返さない**（ADR-0012）。`respondents` は `votes` と `comments` に出てくる `answer_id` の種類の数 |
| F-07 | `POST /api/shares/{share_id}/purchase-click` 本文 `{"product_id": "G0001"}` | 購入ボタンを押した記録を残す | `{"ok": true}` |

## データ
<!-- テーブル定義・保存先の方針 -->

既存の7つの表（`products`・`product_scenes`・`orders`・`order_items`・`reviews`・`users`・`product_facts`）は変えない（N-02、ADR-0005）。次の5つの表を新しく作る（ADR-0010）。名前を入れる列は作らない。ER図は要件定義書 5.1。

| 表 | 列 | 説明 |
| --- | --- | --- |
| `share_lists` | `share_id` VARCHAR(36) 主キー、`created_at` DATETIME | 共有リスト1つにつき1行。番号は UUID（ADR-0007） |
| `share_items` | `share_id` VARCHAR(36)、`product_id` VARCHAR(10)、`position` TINYINT（1〜3）。主キー（`share_id`, `product_id`） | 共有リストに入れた候補 |
| `votes` | `vote_id` INT 自動の番号 主キー、`share_id` VARCHAR(36)、`product_id` VARCHAR(10)、`answer_id` VARCHAR(36)、`voted_at` DATETIME | 賛成。1回の回答（`answer_id`）につき、候補ごとに1行まで（ADR-0014。#20 で相談中）。同じ人かどうかは見分けない（ADR-0010） |
| `comments` | `comment_id` INT 自動の番号 主キー、`share_id` VARCHAR(36)、`product_id` VARCHAR(10)、`answer_id` VARCHAR(36)、`reason_key` VARCHAR(30)（空を許す）、`body` VARCHAR(200)（空を許す）、`created_at` DATETIME | コメント。`reason_key` は `wanted`・`fits`・`memorable`・`practical`・`safe`・`none`（文言は要件.md「実装時に確定するパラメータ」。ADR-0013。#19 で相談中）。賛成した候補には必ず入り、賛成していない候補には入らない。`reason_key` も `body` も空なら保存しない |
| `purchase_clicks` | `click_id` INT 自動の番号 主キー、`share_id`、`product_id`、`clicked_at` DATETIME | 購入ボタンを押した記録（F-07） |

作る SQL は `backend/sql/001_share_tables.sql`（設計.md）。

## エラー時の挙動

| 場面 | API の返し方 | 画面の出し方 |
| --- | --- | --- |
| 存在しない `share_id` | 404 | 「この共有リストは見つかりません」 |
| 候補が0個、または4個以上 | 400 | ボタンを押せないようにしておく |
| POST /api/shares で、products にない商品 ID がある | 400 | 検索結果からしか選べないようにしておく |
| POST /api/shares で、同じ商品 ID が2回ある | 400「同じ商品が2回入っています」 | 同じ商品は2回選べないようにしておく（画面からは起きない） |
| ひとことが201文字以上 | 400 | 入力欄の下に理由を出す |
| `reason_key` が6つの選択肢（`wanted`・`fits`・`memorable`・`practical`・`safe`・`none`）以外 | 400 | 選択肢でしか選べないようにしておく |
| `votes` やコメントの `product_id` が、その共有リストの候補にない | 400 | 候補の中からしか選べないようにしておく |
| `votes` に同じ商品 ID が2回ある | 400 | 画面からは起きない（賛成ボタンは押すたびに付く・外れる） |
| 賛成した候補に `reason_key` がない | 400「賛成した候補の理由を選んでください」 | 送る前に確かめ、同じ文を出す（ADR-0013） |
| 賛成していない候補に `reason_key` がある | 400 | 賛成していない候補では理由を選べないようにしておく（ADR-0013） |
| 同じ候補へのコメントが2つ以上 | 400「1つの候補に付けられるコメントは1つまでです」 | 候補ごとに入力欄を1組だけにしておく（画面からは起きない） |
| 賛成もひとことも空のまま送る | 400 | 「賛成を1つ以上押すか、ひとことを書いてください」と出す |
| DB につながらない | 500（接続情報やエラーの全文は返さない） | 「時間をおいてもう一度お試しください」 |
